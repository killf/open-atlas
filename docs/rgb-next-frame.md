# RGB 下一帧任务与 Atlas 原文对照

当前直接在 RGB 像素空间训练下一帧生成，不使用图像编码器、VAE、预训练权重或潜变量缓存。深度不参与输入、训练目标、损失和输出。这个版本用于简化小规模实验；数据少本身不意味着冻结编码器必然不适合，也不能预先保证去掉它会改善质量。

## 公开事实与实现边界

本次补充核对了官方 Beta API、RTFM 与相关作者代码，详见 [一手资料核对](atlas-source-audit.md)。相机控制任务明确使用目标相机；官方服务可先从普通图像估计相机，本项目尚无此输入前端。

主要依据为 [Atlas 官方技术文章](https://www.worldlabs.ai/blog/atlas) Model Architecture 部分、[DiT 论文](https://arxiv.org/abs/2212.09748)第 3 节，以及 [Rectified Flow 论文](https://arxiv.org/abs/2209.03003)。Atlas 未公开完整网络或训练数据配方，以下不是官方实现声明。

| 原文机制 | 当前实现 | 范围与取舍 |
| --- | --- | --- |
| 多模态序列按元素自回归 | 给定历史 RGB 与相机，生成下一帧 RGB | 仅实现 RGB／相机任务，不复现文本或深度模态 |
| 图像／视频元素具有相机条件 | RGB 附加 Plücker 射线，相机相对第一参考帧 | 目标轨迹为外部条件，不由模型预测 |
| 潜空间扩散 | **改为 RGB 像素空间**，移除独立编解码器 | 用户指定的简化，与 Atlas 官方潜空间设计不同 |
| Rectified Flow | `x_t=(1-t)*noise+t*rgb_next`，回归 `rgb_next-noise` | 每次只计算下一帧 RGB 速度 MSE，无深度损失 |
| Transformer | 小型 DiT、adaLN-Zero 条件调制 | 块结构参考 DiT，不能断言 Atlas 使用相同配置 |
| 时空建模能力 | 历史到目标的时间差与扩散时间独立编码 | 只有静态场景与相机运动，不验证物理模拟 |

“下一帧预测”描述的是生成任务；该帧内部仍通过 rectified-flow 多步去噪，并非一次前向直接回归 RGB。本地直接输出速度是一种参数化选择；Atlas 原文未披露具体预测参数化。[JiT](https://arxiv.org/html/2511.13720v1) 展示了预测干净图像再转换为速度的像素生成路线，当前方案的优化效果仍需对照验证。官方支持 RGB 输入、深度输出，不意味着其预训练必定仅使用 RGB。RGB-only 是本项目的训练范围。

## 数据与坐标

对外任务为 `历史 RGB + 历史相机 + 目标相机 + 视频时间差 → 下一帧 RGB`，不是无相机条件的视频自动续写。相机条件依据见官方 [How to use Atlas](https://atlas-beta.worldlabs.ai/docs/how-to-use-atlas)。数据集只索引 `rgb`、`K`、`c2w`、时间与划分字段。每个目标为紧接可见历史之后的一帧，默认从历史中选取第一帧和最近一帧；目标和未来图像不作为条件。训练始终使用干净历史，这仍不是 Diffusion Forcing。

相机编码使用 `inverse(T_world_from_first) @ T_world_from_camera`。这一相对坐标选择参考 [CAT3D](papers/cat3d-2405.10314.pdf)第 3.1 节，统一改变世界坐标不会改变输入射线。输出元数据仍保存原始场景相机变换。CAT3D raymap 记录原点与方向，本项目另采用 CameraCtrl 风格 Plücker moment／方向；两者表示不同，均不能说成 Atlas 已公开的具体相机编码。

沿用 `data/rendered/replica_rgb_v2/`：训练、验证、测试分别使用 apartment_0／apartment_1／apartment_2，60 段视频共 1392 张 RGB，1104／90／138 个目标。当前数据目录没有深度文件或字段，目标图像与历史实验相同。

## 像素空间模型

输入图像为 `[B,3,64,64]`，范围 [0,1]。与六通道相机射线拼接后，单层可训练 patch 投影将每个 4×4 区域映射为一个 token；每帧共 256 个 token。每个 RGB patch 有 48 个值，小于隐藏维度 128，避免输出投影维度不足。这个投影是 Transformer 的输入层，不是独立图像编码器，没有重建目标或预训练步骤。

默认上下文两帧，4 层、128 维、4 个注意力头；输出层直接还原 `[B,3,64,64]` 的像素速度。历史不能注意到加噪目标，目标可使用历史和自身的 patch。采样从三通道高斯噪声开始，Euler 积分结束后才裁剪到 [0,1]，以保持中间流路径不被截断。

生成 RGB 直接反馈到历史，只有开头的参考帧来自真实图像。输出包括 RGB PNG、MP4、相机元数据与 `rgb.npz`。当前只保留两帧历史，未实现多模态统一序列、空间检索或 KV-cache。检查点格式为 3，标记 `representation=rgb_pixels`，不包含编解码器。旧潜空间和 RGBD 检查点明确拒绝加载，需在当前实现重新训练。

## 验证与实验协议

27 项测试通过，覆盖无深度／无编解码器训练、三通道输出、相机条件、世界坐标变换不变性、流积分、RGB 裁剪反馈，以及删除全部未来图像后同种子生成完全相同结果。同时验证奇数尺寸 RGB 可正常生成视频：仅 MP4 补齐偶数边长，不改变原始图像和相机参数。保留真实 Blender 渲染与数据下载测试。

新实验固定 1000 步、64×64 RGB、4×4 patch、batch 4、AdamW 3e-4、种子 42、CPU 2 线程。模型有 1,327,920 个可训练参数。与上一版潜空间实验采用相同数据、步数和骨干宽度／层数；像素版每帧 256 个 token，潜空间版为 64 个，计算量与参数量不同。验证流损失使用独立场景与固定噪声，跨表示的流损失数值不直接比较。

最终评测每段只给首帧真实 RGB 和相机序列，Euler 20 步自由滚动；独立测试场景共 6 条轨迹、138 帧，统一缩放到 32×32 评分。汇总所有像素误差计算 RGB PSNR／MAE，并报告重复首帧基线。结果不能证明 Atlas 级质量或多场景泛化能力。

新检查点位于 `runs/rgb-pixel-next-frame-v1/last.pt`，训练日志位于同目录 `train.log`；评测输出位于 `outputs/rgb-pixel-next-frame-v1-eval/`。完整命令、检查点哈希、训练统计和逐轨迹指标见 [结构化记录](rgb-pixel-next-frame-results.json)。

此前 TAESD 潜空间实验保留在 [历史结构化记录](rgb-next-frame-results.json)，其实现对应提交 `ea5e987`，本地检查点仍在 `runs/rgb-next-frame-v1/last.pt`。对应 [TAESD MIT 许可](asset-licenses/TAESD.txt) 为历史权重保留；当前代码无需下载它。


## 1000 步实际结果

训练和独立测试评测均已完成。训练最后 20 步平均流损失为 0.1035，最终验证流损失为 0.1186；这些数值属于当前像素表示，不能与历史潜空间损失直接比较。

| 同一 32×32 评分协议，138 个测试目标 | RGB PSNR |
| --- | ---: |
| 当前 RGB 像素模型，1000 步 | 11.84 dB |
| 历史 RGB 潜空间模型，1000 步 | 11.37 dB |
| 重复首帧基线 | 17.00 dB |

当前 RGB MAE 为 0.1955（范围 [0,1]）。PSNR 略高于历史潜空间实验，但每帧 token 数从 64 增加为 256，编解码器、表示和投影也不同；不能将差异直接归因于移除编码器。结果仍低于复制首帧，未证明有效的新视角生成质量。只有一个训练场景与一个独立测试场景，结论不能推广到一般场景。本轮未根据测试结果继续调参。
