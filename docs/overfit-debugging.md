# 8 帧过拟合失败排查

过拟合失败说明当前训练流程没有达到记忆目标，必须先排查；它本身不能区分实现错误、优化问题和训练步数不足。本轮保持相机条件、纯 RGB、无编解码器与模型结构不变，先定位训练端问题。

原检查固定的是 8 张干净 RGB；每次更新仍重新抽取高斯噪声和扩散时间，因此输入不是固定的 7 对张量。与普通确定性回归的固定批次过拟合检查相比，它还要求模型学到跨噪声、跨时间的条件生成行为。两种检查需要分别记录，不能混用通过结论。

## 已核对的路径

- 数据的 7 个目标与真实历史逐项对应，RGB 范围为 [0,1]；第一目标的两帧历史重复是预期行为。
- patch 输出排列与图像还原一致；PyTorch 布尔注意力遮罩只阻止历史读取当前目标，当前目标能读取历史。
- 流方向为 t=0 高斯噪声到 t=1 图像；损失两侧使用相同分母，20 步采样与训练的方向一致。
- 参数与历史条件存在有效梯度。一个仅靠历史区分两个目标的 8×8 最小任务，301 次更新后纯噪声输入预测达到 38.96 dB；交换历史后，对交换后的目标达到 40.15 dB。该任务只验证条件通路能够工作，不代表真实轨迹已学好。

以上检查及独立代码审查暂未发现能解释失败的确定性索引、遮罩或符号错误；单元测试通过也不等于真实数据已收敛。

进一步只保留第一个真实目标，从首轮检查点开始固定 t=0、使用新噪声续训 400 步（AdamW 3e-4，batch 1），直接预测达到 32.34 dB。这表明骨干也能拟合真实图像；它不覆盖七个目标、整个扩散时间区间或完整采样，不能用来宣称原检查通过。

## 找到的确定性评测 bug

独立 `evaluate_overfit` 重建数据集时遗漏了检查点的 `context_frames`，始终按默认两帧历史评分。非默认配置会静默改变模型条件。已改为恢复保存值；回归测试用真实的一帧历史检查点观测三个种子的采样输入，修正前为 `[2,2,2]`，修正后为 `[1,1,1]`。本次失败的检查点本来就是两帧，因此该 bug 不解释首轮指标。

## 时间采样与损失权重失衡

首轮仅采用了 JiT 的图像预测转速度公式，却仍均匀采样时间。对干净图像预测，当前速度损失等价于：

```text
loss = mean((I_hat - I)^2 / max(1-t, 0.05)^2)
```

均匀时间下权重的期望为 39，t>0.9 的 10% 样本贡献其中约 77%。这不是除法或求导错误，但会改变小批次的优化重点，不能因公式正确就认定训练配方合适。

用首轮检查点、相同 7 个目标和相同噪声（种子 17）测得，t=0 的梯度范数为 0.09274，t=0.99 为 30.97792；实际训练统一裁剪范数到 1。该测量使用完整 7 目标批次，不能代替实际 batch 4／3 下的梯度分布。

[JiT 作者代码](https://github.com/LTH14/JiT/blob/cbc743a2ada5e9762697da2c83f8c4f8379e8c17/denoiser.py) 及同版本 `main_jit.py` 使用 `t=sigmoid(N(-0.8,0.8²))`。该分布的平均权重约为 2.96，减少接近干净端的极高权重样本。本轮曾将默认时间分布改为此设置试验，保留插值、速度损失、分母保护及采样器；从头复测未改善完整生成，因此已恢复均匀时间分布。检查点记录 `time_sampling`，旧格式 4 检查点不含此字段时按历史均匀分布记录；推理结构兼容。

这项对照没有定位首轮失败的根因，也不意味着使用了 JiT 或 Atlas 的全部训练设置。

## 匹配的短续训对照

从相同首轮检查点开始，重置 AdamW（lr=3e-4），全批次 7 个目标，继续 150 步，噪声与时间的随机源均固定为种子 42。对照均先取相同的均匀随机数；实验组经正态逆 CDF 后转换为 logit-normal，因此每步图像噪声保持相同。只有时间分布变化。另列固定 t=0 的诊断，不将其视为完整流训练。

| 训练时间设置 | t=0 直接预测 PSNR | 20 步生成 PSNR |
| --- | ---: | ---: |
| 续训前 | 20.97 dB | 23.67 dB |
| 均匀分布，续训 150 步 | 18.01 dB | 24.14 dB |
| logit-normal，续训 150 步 | 24.18 dB | 24.73 dB |
| 固定 t=0，续训 150 步 | 24.51 dB | 21.14 dB |
| 均匀分布，lr=3e-3，续训 150 步 | 17.10 dB | 23.89 dB |

这里使用种子 17 的单次噪声、裁剪后的浮点 RGB 计算原生 64×64 PSNR，不量化到 PNG。它与正式三个种子的量化评测协议不同。结果支持时间分布影响高噪声端学习；固定 t=0 不能替代完整时间区间训练。单个续训种子和不足 1 dB 的生成改善，不能作为完整修复证明。

最后一行对照仍沿用均匀分布，与第一条续训仅学习率不同；结果也未通过，未修改默认学习率。

## 固定输入的有限批次拟合

从首轮检查点开始，固定全部 7 个目标、噪声种子 17、扩散时间 t=0.5；每次提供完全相同的训练张量，AdamW 3e-4，batch 7，范数裁剪 1。250 次额外更新的汇总原始浮点 PSNR 从 22.99 提升到 **30.48 dB**，最差目标为 29.38 dB；损失从 0.020085 降至 0.003585。

该结果验证损失、反向传播和输出还原能够共同拟合这批固定输入。由于 `x_t=0.5*noise+0.5*target` 含有目标信息，且训练、评分使用相同输入，它不能作为纯噪声生成成绩，也不表示原方案 1 通过。它说明“固定 8 张 RGB 的随机扩散训练未通过”与“固定张量批次无法拟合”不是同一个结论；本轮尚未定位随机条件生成失败的具体原因。

## 从头复测

实验实现提交为 `9c0444c`（logit-normal，已撤回默认设置）。相同 8 帧从随机初始化训练 1000 步，输出到新的目录，不沿用任何续训诊断权重；以下是当时执行的命令，复现该实验需使用该提交：

```bash
python -u -m open_atlas.overfit \
  --trajectory data/rendered/replica_rgb_v2/train_view_0/apartment_0_truck_000/transforms.json \
  --output runs/rgb-image-overfit-v2 --frames 8 --steps 1000 \
  --image-size 64 --sampling-steps 20 --seed 42 --device cpu
```

源文件及 8 张 RGB 哈希与首轮一致；模型、优化器超参数、两帧上下文和评分协议保持一致。时间抽样从 `rand` 变为 `randn` 会改变后续全局随机序列，因此不能把两个从头训练视为逐更新严格配对。

仍按原定标准：三种子汇总至少 30 dB，且高于复制上一帧 3 dB，不降低门槛。实际完成后结果如下：

| 配方 | 三种子汇总 PSNR | MAE | 复制上一帧 PSNR | 通过 |
| --- | ---: | ---: | ---: | --- |
| 首轮均匀时间，1000 步 | 23.6884 dB | 0.040678 | 25.5837 dB | 否 |
| logit-normal，1000 步 | 23.3139 dB | 0.039780 | 25.5837 dB | 否 |

新实验的三个种子分别为 23.3167／23.3105／23.3145 dB。它没有改善完整生成指标，因此短续训改善不足以确定时间分布是根因。失败权重与预测保留在 `runs/rgb-image-overfit-v2/`，不覆盖首轮文件。

新检查点在固定噪声种子 17 下，1／5／20 步生成 PSNR 为 22.65／23.93／23.31 dB；不能靠增加采样步数解决。交换批内历史 RGB，或连同历史射线和视频时间一起交换，20 步生成 PSNR 均仍约为 23.311 dB；清零历史 RGB 为 23.158 dB。目标相机不变，因此这些实验不能证明模型完全无条件，但表明它在这条真实轨迹上没有充分利用历史差异。

当前未查到能解释首轮失败的确定性张量实现错误。历史条件利用不足已经复现，其具体优化或结构原因尚未定位；不能称为模型正常，也不能称为原问题已修复。不扩大完整数据训练。

新增的历史帧数回归测试已先复现失败；默认时间分布撤回后，最终完整 **32 项测试通过**。时间分布实验及其测试保留在 Git 历史，最终代码没有增加该采样分支。完整指标、协议及哈希见 [结构化记录](overfit-debugging-results.json)。
